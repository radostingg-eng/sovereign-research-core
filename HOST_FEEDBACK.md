# Privacy-bounded host feedback

Hosts improve the shared runtime by reporting generic failures. They never
publish the private evidence that exposed the failure.

## Automatic signals

At the end of a scheduled cycle, a host may post at most one automatic issue
to `radostingg-eng/sovereign-research-core`. The signal has exactly five
fields:

```json
{
  "kind": "runtime_refusal",
  "core_commit": "0123456789abcdef0123456789abcdef01234567",
  "error_code": "missing_research",
  "occurrence_bucket": "2-5",
  "synthetic_test_needed": true
}
```

Allowed `kind` values:

- `runtime_refusal`
- `runtime_error`
- `capability_gap`

Allowed occurrence buckets:

- `1`
- `2-5`
- `6+`

`error_code` must be either an exact key in
`runtime.host_feedback.REFUSAL_GUIDANCE` or one of:

- `connector_capability_missing`
- `documentation_gap`
- `profile_isolation_failure`
- `runtime_contract_failure`
- `scheduled_task_failure`
- `workflow_failure`

No other fields are allowed. In particular, never include free text,
instruments, values, quantities, dates, timestamps, cycle IDs, record IDs,
paths, connector results, profile names, or operator statements.

The issue title is:

```text
[host-signal] <error_code>
```

The body contains only the five fields plus the fingerprint generated by
`runtime.contribution.signal_fingerprint`.

Before creating an issue, search existing open and closed core issues for the
same fingerprint. If found, do not create another issue. Add one fixed comment:

```text
Another profile observed this signal. Occurrence bucket: <bucket>.
```

Do not add context to the comment.

## Failure behavior

If the GitHub issue cannot be created, write the exact five-field JSON to:

```text
feedback_signals/pending/<error_code>-<core-short-sha>.json
```

Retry on a later hourly run. Do not ask the operator and do not block the
research cycle.

After an issue is created or deduplicated, move the signal to:

```text
feedback_signals/shared/<error_code>-<core-short-sha>.json
```

Add only `shared_issue_url` to the private receipt. The URL is private profile
state and is never included in the shared issue.

## Rich feedback

Feature ideas, unknown defects, reproductions, and explanatory prose are never
posted automatically. Store them under `feedback_staging/` in the private
profile. They require deterministic sanitization or human review before
sharing.

An automatic signal is deliberately small. It answers: **which known shared
contract failed, against which core version, and how often?** It does not try
to explain the operator context that revealed it.
